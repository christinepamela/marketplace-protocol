## Architectural Principles (Always-On)

1. Protocol is passive infrastructure — 0.5%+0.5% from payouts at escrow release, never added to buyer's total.
2. Federation is the goal from day one.
3. Cryptographic identity (secp256k1) — protocol never holds passwords/keys/KYC docs.
4. Nostr is plumbing, Rangkai owns UX and search.
5. Small business first — hide complexity. If something seems hard, check for the simpler framing first.
6. Bitcoin is the invisible rail — v1 pays out BTC/USD directly, invisible conversion is v1.5 (R11).
7. Terminology: seller, buyer, logistics — not vendor, provider, courier.
8. No centralized consolidation hubs — logistics stays inside the decentralized pool.

### D35 — Buyer RFQ accepts bleeding into product page price — ✅ DONE S36

**What was fixed:** Two-part fix.

**Schema (Supabase SQL editor):**
```sql
ALTER TABLE shipping_quotes
  ADD COLUMN context text NOT NULL DEFAULT 'seller_standing'
  CHECK (context IN ('seller_standing', 'buyer_rfq'));

UPDATE shipping_quotes sq
SET context = 'buyer_rfq'
WHERE sq.product_id IS NOT NULL
  AND EXISTS (
    SELECT 1 FROM quote_requests qr
    WHERE qr.product_id = sq.product_id
  );
```
Back-fill ran clean (0 rows affected — no existing buyer RFQ rows matched after S35 test cleanup).

**Code (`src/core/layer3-logistics/quote.service.ts`):**
- `submitQuote()` — sets `context: 'seller_standing'` in insert (all provider-submitted quotes are seller context by definition)
- `acceptQuote()` — computes `finalContext` at accept time by checking whether a `quote_requests` row exists for this product from a non-vendor requester. Sets `context: finalContext` on the update.
- `getAcceptedQuoteForProduct()` — added `.eq('context', 'seller_standing')` filter so product page and cart always show the seller's standing price, never a buyer's personal RFQ accept.

**Effect:** After one buyer accepts an RFQ quote at checkout, other buyers' product pages and cart shipping summaries are unaffected — they still see the seller's accepted standing quote.

## Troubleshooting Reference

### API Server Won't Start
`Router.use() requires a middleware function but got a Object` → empty/misconfigured route file in `routes/index.ts`.

### "TypeError: fetch failed" on Startup
Supabase paused — restore at supabase.com/dashboard.

### SDK changes not taking effect
Full D25 sequence required. Verify: `findstr /n "methodName" rangkai-marketplace\node_modules\@rangkai\sdk\dist\modules\logistics.js`

### Country field in checkout or ProductForm not storing ISO code
CountryCombobox (D19, S36) is in place — user must select from the dropdown, not just type and leave. If the field is blank after typing, the user didn't select a country from the list. The pool flow buttons are disabled until `shippingAddress.country` is a non-empty string (set only on dropdown selection).

### Direct quote request blinks back to browse state
Check API server terminal for the error. With D19 in place this should no longer happen for country validation failures. If it recurs, check the actual error in the terminal — likely a different validation failure.

### Wrong provider showing in logistics-marketplace header
D34 fixed S36. `ProviderContext` now calls `GET /api/v1/logistics/providers/me` directly. If it recurs, check that the API server is running and the token in localStorage is valid.

### Buyer sees wrong shipping price in cart
D35 fixed S36. `getAcceptedQuoteForProduct()` now filters to `context = 'seller_standing'`. If wrong pricing reappears, check that the seller's standing quote has `context = 'seller_standing'` in the DB:
```sql
SELECT id, status, context, price_fiat
FROM shipping_quotes
WHERE product_id = 'bad3b0e0-5b97-413a-8c5c-cfd3812a51bd'
AND status = 'accepted';
```

### `quote-requests/buyer/pending` returning 500
The nested Supabase join on `shipping_quotes` inside a `quote_requests` query fails due to ambiguous FK on `product_id`. Fixed S34 by splitting into two queries. If it resurfaces, check the two-query version is in place in `logistics.routes.ts`.

### Opportunities page shows "Submit quote" on already-quoted requests
D34 part 2 — submitted state is session-local only. Refresh resets it. Permanent fix: pre-fetch provider's pending quotes on page load and mark those cards as quoted. Not yet done — still open.

### Order detail page showing subtotal and total but no shipping line
D36 fixed S36. If it reappears, check that `order.logisticsCost` is non-zero in the DB for that order. The line only renders when `(order as any).logisticsCost > 0`.
