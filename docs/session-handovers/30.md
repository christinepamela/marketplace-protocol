## Why Rangkai Exists

Pam wrote about this in her 2025 Medium piece **"When Global Trade Leaves Small Businesses Behind"**
(https://medium.com/@christinepamela/when-global-trade-leaves-small-businesses-behind-d9e31b6c292a).
Read it before doing any architecture work. The technical decisions follow from the purpose.

Short version: global trade infrastructure was built for large corporations. A Penang batik weaver, a Sabah honey producer, a Klang furniture maker — they exist, they make excellent products, they have buyers waiting in Berlin and Toronto, but they're functionally invisible. Rangkai is infrastructure for them. Not a marketplace — a protocol that enables marketplaces. Federation is the point.

## Architectural Principles (Always-On)

1. **The protocol is passive infrastructure** — provides rails, never enforces policy. 0.5% from seller payout + 0.5% from logistics payout at escrow release. Never charged on top of buyer's total.
2. **Federation is the goal from day one** — not v2, the reason the protocol exists. Every design must preserve the federation path. v1 is "one marketplace done well, designed to federate."
3. **Cryptographic identity** — secp256k1 keypairs (same curve as Bitcoin and Nostr). Protocol never holds passwords, private keys, or KYC documents.
4. **Leverage existing ecosystems without becoming dependent** — Nostr is plumbing, Rangkai owns UX and search.
5. **Small business first** — hide complexity, deliver capability.
6. **Bitcoin is the invisible rail** — users see their currency. Bitcoin settles underneath. For v1, sellers/logistics receive BTC or USD directly. Invisible conversion (R11) is v1.5.
7. **Terminology is canonical** — seller, buyer, logistics. Not vendor, provider, courier. Enforce in all new code.

### Logistics Architecture — Fully Designed

The entire B1 job list was designed from scratch this session. Key decisions made and locked:

**Fee model corrected.** The old spec formula (`buyer pays = product + logistics + fees`) was wrong. Correct model: buyer pays product + logistics only. Protocol takes 0.5% from seller's payout and 0.5% from logistics payout at escrow release. `LOGISTICS_ARCHITECTURE.md` section 13 must reflect this — if not already corrected, do it in Session 31 before touching any checkout code.

**Terminology locked.** seller / buyer / logistics. All new code and docs use these terms. Migration from vendor/provider is ongoing — don't use the old terms in new code.

**Seller quote rules.** KYC sellers must have at least one logistics quote (firm or estimated) before a product can be published. Anon sellers manage their own logistics and cannot access the logistics pool. Multiple quotes per product are allowed and encouraged — competitive quoting between logistics providers is the point.

**Incoterms in v1.** Support EXW, FOB, DAP, DDP. DAP is default (seller arranges shipping, buyer pays duties on arrival). UI must translate Incoterms into plain buyer language — "Door to door, you pay import duties on arrival" not "DAP".

**Two-way escrow split.** On delivery confirmation, escrow must produce two payouts:
- Seller receives `product_subtotal × 0.995`
- Logistics receives `logistics_cost × 0.995`
- Protocol retains 1% total
This is new code — `createVendorPayout()` in `bitcoin.service.ts` currently pays one party only. A `createSplitPayout()` function is needed (L10).

**Currency for v1.** USD throughout. D6 (currency layer) deferred. Bitcoin escrow splits into two BTC transactions on delivery. R11 (invisible Bitcoin rail via Strike/Lightspark) is v1.5 — **Pam's offline task: check Strike and Lightspark for MYR payout support in Malaysia before Session 31.**

**Anon identity.** Already in codebase, not launched yet. Anon sellers cannot use logistics pool. No code enforcement needed yet since not launched, but must be enforced when launched.

## Troubleshooting Reference

### API Server Won't Start
**Symptom:** `Router.use() requires a middleware function but got a Object`
**Cause:** A route file in `routes/index.ts` is empty or has wrong export.
**Fix:** Check the line number, find the offending file, remove or fix the mount.

### "TypeError: fetch failed" on Startup
**Cause:** Supabase is paused.
**Fix:** Go to supabase.com/dashboard, restore project, wait 30s.

### Bitcoin 429 Errors from Blockstream
**Cause:** Too many requests — 700 req/hour free tier per IP.
**Fix:** Now graceful (B12 ✅) — scheduler retries automatically on next poll cycle. No more 500 errors.
**Production fix:** R10 (BTCPay) eliminates polling entirely. Target v1.5.
