### D43 — RFQ broadcast dedup — ✅ DONE
**What:** Both `POST /logistics/quote-requests` and `POST /logistics/quote-requests/buyer` now
reuse and refresh an existing open request instead of inserting a duplicate.
**Why it mattered:** Every publish and every buyer request created a new open row. `custom`
(`bad3b0e0`) had accumulated 4, with 2 open. Providers saw the same job repeatedly.
**How:** Look up the oldest matching open row; UPDATE the full payload if found, INSERT if not.
Response carries `reused: true|false`.

Reading both handlers settled the open spec question — the keys must differ:
- **Seller path:** `product_id + requester_did + target_provider_id IS NULL + open`. This path's
  schema has no `target_provider_id` field, so broadcasts are always null-target.
- **Buyer path:** `target_provider_id` by value, because L15d direct requests are legitimately
  separate rows. `destination_country` stays in the payload, not the key, so a buyer changing
  their shipping address refreshes rather than duplicates.

Refreshing the **payload** matters as much as the expiry: a weight corrected from 0.7 to 2.4 kg
must not leave providers quoting the old figure.
**Files changed:** `src/api/routes/logistics.routes.ts` (+119 / −37). Server-side only — no SDK
change, no rebuild. Confirmed by reading `packages/sdk/src/modules/logistics.ts` and
`components/vendor/ProductForm.tsx` rather than assuming.
**Tested:** 9 curl calls, 2 new rows created, both intended.
