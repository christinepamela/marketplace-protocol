## Architectural Principles (Always-On)

1. Protocol is passive infrastructure — 0.5%+0.5% from payouts at escrow release, never added to buyer's total.
2. Federation is the goal from day one.
3. Cryptographic identity (secp256k1) — protocol never holds passwords/keys/KYC docs.
4. Nostr is plumbing, Rangkai owns UX and search.
5. Small business first — hide complexity. If something seems hard, check for the simpler framing first.
6. Bitcoin is the invisible rail — v1 pays out BTC/USD directly, invisible conversion is v1.5 (R11).
7. Terminology: seller, buyer, logistics — not vendor, provider, courier.
8. No centralized consolidation hubs — logistics stays inside the decentralized pool.

### D24 — Seller self-declared "estimated" shipping quote at product upload — ✅ DONE S38

**Design decisions confirmed with Pam:**
- A real accepted provider quote **automatically supersedes** the seller estimate (estimate marked `rejected`) — sellers never clean up manually. Keep v1 simple; air/sea freight mode choice etc. is later.
- Buyer-facing label: **"Seller's estimate"** — plainly stated, understood. (Go-to-market copy may later soften to "estimated shipping" with a smaller-font note.)
- Estimate inserts **directly as `status: 'accepted'`** (seller is both author and accepter), `context: 'seller_standing'`, `is_seller_estimate: true`, `provider_id: null` — so buyer-facing display flows through the exact same query path as a real accepted quote.
- Seller estimates **always display "(estimated)", never "firm"**, regardless of `valid_until` (which is set 1 year out just so expiry logic never touches it).
- UI: **create mode only, KYC sellers only.** Edit-mode estimate management can join the L13 quotes page later if wanted. Fires for both draft and publish saves. Failures alert the seller (unlike the best-effort RFQ broadcast).

**What was built:**
1. **Schema (Supabase SQL, applied directly):** `provider_id` DROP NOT NULL; `is_seller_estimate boolean NOT NULL DEFAULT false`; CHECK constraint `quote_has_provider_or_estimate` (`provider_id IS NOT NULL OR is_seller_estimate = true`); **plus D29's index** (below).
2. **`quote.service.ts`:** new `submitSellerEstimate()` (validates price, blocks if an accepted standing quote already exists, readable errors distinguishing "already has a seller estimate" vs "already has an accepted provider quote"). `acceptQuote()` supersede logic: in seller context, an existing accepted **seller estimate** is marked `rejected` and the accept proceeds; a real accepted quote still blocks. Guard query also gained the missing `.eq('context', 'seller_standing')` filter. `getAcceptedQuoteForProduct()` forces `priceStatus: 'estimated'` when `is_seller_estimate`.
3. **`logistics.routes.ts`:** `POST /logistics/quotes/seller-estimate` — auth'd, product-owner-only (same ownership pattern as L13), Zod schema `sellerEstimateSchema`.
4. **SDK:** `sdk.logistics.submitSellerEstimate()` added; `ShippingQuote` type in `packages/sdk/src/types.ts` updated to the real table shape (`order_id`/`provider_id` nullable, `product_id`, `quote_type`, `context`, `is_seller_estimate`).
5. **`ProductForm.tsx`:** estimate block in the Logistics section (price + days), with nudge copy steering sellers toward real pool quotes. Separate `sellerEstimate` useState — deliberately not in FormData (it's not product data). Submit fires after product create, after the L12 RFQ broadcast.
6. **`app/products/[id]/page.tsx`:** shipping block now handles `provider: null` — shows "Seller's estimate" when `is_seller_estimate`, `provider?.business_name || 'Logistics provider'` otherwise. **This fixed a real crash**: the estimate was the first-ever null-provider quote and the L14 block did `shippingQuote.provider.business_name` unguarded → "Failed to Load Products / Cannot read properties of null".

**CartSummary needed no change** — it never reads provider name; showed "$14.00 (estimated)" correctly out of the box.

**Tested end-to-end (all passed):**
- curl: create estimate (201, all flags correct) → duplicate blocked → buyer-facing endpoint returns `priceStatus: "estimated"`, `provider: null` → Hash Heel forbidden 403 on Bitshop's product → BitHaul submits real $16 quote → Bitshop accepts → estimate auto-flipped to `rejected` in DB, $16 shows "firm" with full provider object.

CREATE UNIQUE INDEX one_accepted_standing_quote_per_product
  ON shipping_quotes (product_id)

### D40 discovered — `acceptQuote()` context misclassification (NEW tech debt, Medium-High)

While verifying D24 against "custom", found all 4 accepted quotes on it were `context: buyer_rfq` — including `8a54f596` ($15 BitHaul standing quote) which the S37 handover recorded as `seller_standing`. Root cause: `finalContext` (and the guard, and reject-competing logic) infer buyer-RFQ context from whether **any** `quote_requests` row exists for the **product** from a non-vendor — not whether **this quote** answered an RFQ. Once any buyer has RFQ'd a product, every subsequent accept gets stamped `buyer_rfq`, hiding the standing quote from product/cart display. Full entry + proper fix (nullable `quote_request_id` on `shipping_quotes`, set at submit) in TECH_DEBT.md D40.

**Data repaired by hand S38:** `8a54f596` restored to `seller_standing`; stale buyer-RFQ accepted quotes on "custom" deleted **except** `d09ea582` ($17), which is FK-referenced by order `ORD-2026-205695-FXK` and must stay; Bitty Buy's open `quote_requests` closed.

## Troubleshooting Reference

### Health endpoint says healthy but nothing works
Health check doesn't touch the DB. If the API terminal shows `[Scheduler] ... TypeError: fetch failed`, Supabase is paused — restore at supabase.com/dashboard. Confirm real DB connectivity with a login curl, not /health.

### Seller-estimate endpoint returns "already has a seller estimate" / "already has an accepted provider quote"
Working as designed — one accepted standing quote per product (D29 index enforces at schema level too). To replace an estimate: accept a real provider quote (auto-supersedes). There is no edit-estimate path in v1.

### Product page shows no shipping block despite a known accepted quote
Check the quote's `context` — if `buyer_rfq`, display correctly ignores it. If a quote that *should* be `seller_standing` is stamped `buyer_rfq`, that's D40 (context inference bug). Repair by hand: `UPDATE shipping_quotes SET context = 'seller_standing' WHERE id = '<id>';`

### Deleting test shipping_quotes fails with FK error on orders
`orders.logistics_quote_id` references quotes. Exclude them:
```sql
AND id NOT IN (SELECT logistics_quote_id FROM orders WHERE logistics_quote_id IS NOT NULL)
```

### Provider quote shows "(estimated)" unexpectedly
Its `valid_until` passed — L14's designed firm→estimated conversion, not a bug (and not a seller estimate; those say "Seller's estimate"). D23 (seller notification at conversion) is still open.

### "getIdentity is not a function" in browser console on product pages
B17, known, graceful. S39 priority #3.

### SDK changes not taking effect
`cd packages\sdk && npm run build`. Verify junction: `dir node_modules\@rangkai` should show `<JUNCTION>`.

### Trust/sanctions endpoint returns UNAUTHORIZED
Login first for a Bearer token:
```
curl -s -X POST http://localhost:3000/api/v1/identity/login -H "Content-Type: application/json" -d "{\"email\":\"testBit2@test.com\",\"password\":\"bitshop123\"}"
```
