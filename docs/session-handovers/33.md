**Critical — read this every time you touch `packages/sdk/src/`:**

`packages/sdk` compiles via `tsc` to `packages/sdk/dist`, which `rangkai-marketplace` depends on via `"@rangkai/sdk": "file:../packages/sdk"` in its `package.json`. On this machine, that `file:` dependency was installed as a **physical copy**, not a live link — confirmed via `dir` showing `<DIR>` rather than `<SYMLINKD>`/`<JUNCTION>`. That means:

1. Editing `packages/sdk/src/` and running `npm run build` updates `packages/sdk/dist` — but **does not** update `rangkai-marketplace/node_modules/@rangkai/sdk`, which is a frozen snapshot from whenever it was first installed.
2. Full fix, every time, in order:
   ```
   rmdir /s /q "C:\Users\chris\marketplace-protocol\rangkai-marketplace\node_modules\@rangkai\sdk"
   cd C:\Users\chris\marketplace-protocol\rangkai-marketplace
   npm install
   rmdir /s /q .next
   npm run dev
   ```
3. Yes, all three steps (reinstall the copy, clear `.next`, restart) were needed this session — reinstall alone wasn't enough because Next.js's own build cache also held stale module resolution.

This is tracked as **D25** (real fix: convert repo to npm workspaces) — until that's done, expect to repeat the four-command sequence above every single time `packages/sdk/src/` changes. Don't try to shortcut it; both S32 and S33 lost real time assuming a rebuild-and-restart was sufficient.

## Architectural Principles (Always-On)

1. Protocol is passive infrastructure — 0.5%+0.5% from payouts at escrow release, never added to buyer's total.
2. Federation is the goal from day one.
3. Cryptographic identity (secp256k1) — protocol never holds passwords/keys/KYC docs.
4. Nostr is plumbing, Rangkai owns UX and search.
5. Small business first — hide complexity. If something seems hard, check for the simpler framing first.
6. Bitcoin is the invisible rail — v1 pays out BTC/USD directly, invisible conversion is v1.5 (R11).
7. Terminology: seller, buyer, logistics — not vendor, provider, courier.
8. No centralized consolidation hubs — logistics stays inside the decentralized pool. Where centralized platforms (Alibaba/China freight-forwarder model) solve multi-item shipping by routing through a single consolidation warehouse, Rangkai routes bundled requests through the same peer logistics pool used for individual quotes. Consolidation is a matching problem for the pool, not infrastructure Rangkai owns. (S33, R23)

Confirmed against the real accepted quote row already in the DB from L13 testing.

**Design decision (Pam, S33) on firm vs. estimated:** sellers can satisfy the mandatory pre-publish quote requirement two ways — a real provider quote (firm, expires) or a self-declared estimate (not yet buildable, see D24). When a firm quote's `valid_until` passes, it should auto-convert to "estimated" for buyer display rather than disappearing — gives breathing room, but the seller now bears the gap between that stale number and real fulfillment cost, and should be notified when this happens (not yet buildable either, see D23). **L14 only implements the display-side computation; the seller-facing self-estimate path (D24) and the expiry notification (D23) are explicitly out of scope for L14, deferred.**
