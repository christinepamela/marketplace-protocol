## Why Rangkai Exists

Pam wrote about this in her 2025 Medium piece **"When Global Trade Leaves Small Businesses Behind"**
(https://medium.com/@christinepamela/when-global-trade-leaves-small-businesses-behind-d9e31b6c292a).
Read it before doing any architecture work. The technical decisions follow from the purpose.

Short version: global trade infrastructure was built for large corporations. A Penang batik weaver, a Sabah honey producer, a Klang furniture maker — they exist, they make excellent products, they have buyers waiting in Berlin and Toronto, but they're functionally invisible. Rangkai is infrastructure for them. Not a marketplace — a protocol that enables marketplaces. Federation is the point.

## Architectural Principles (Always-On)

1. **The protocol is passive infrastructure** — provides rails, never enforces policy. 0.5% from seller payout + 0.5% from logistics payout at escrow release. Never charged on top of buyer's total.
2. **Federation is the goal from day one** — not v2, the reason the protocol exists. Every design must preserve the federation path.
3. **Cryptographic identity** — secp256k1 keypairs. Protocol never holds passwords, private keys, or KYC documents.
4. **Leverage existing ecosystems without becoming dependent** — Nostr is plumbing, Rangkai owns UX and search.
5. **Small business first** — hide complexity, deliver capability.
6. **Bitcoin is the invisible rail** — users see their currency. Bitcoin settles underneath.
7. **Terminology is canonical** — seller, buyer, logistics. Not vendor, provider, courier. Enforce in all new code.

### L10 — Escrow split payout on delivery — ✅ Done S31

**2 files changed:**

`src/core/layer2-transaction/bitcoin.service.ts` — new public method `executeSplitPayoutBTC()` added before the PRICE FEED section.

How it works:
- Takes `orderId`, `sellerBtcAddress`, `productSubtotalUsd`, and optionally `logisticsBtcAddress` / `logisticsCostUsd`
- Verifies escrow payment is confirmed on-chain via `checkPaymentStatus()`
- Converts USD amounts to satoshis at current BTC price
- Applies 0.5% protocol fee to each side: `sellerSats = toSats(productSubtotalUsd) × 0.995`, `logisticsSats = toSats(logisticsCostUsd) × 0.995`
- Builds a **single PSBT** with both outputs — one on-chain transaction, both parties paid in the same broadcast
- If `logisticsCostUsd = 0` or no logistics address provided, only the seller output is added (Path B2 orders)
- Remaining sats (protocol fee + dust) stay in the escrow address for periodic sweeping — no change output
- Logs both payouts to `bitcoin_vendor_payouts` with `txid`, `status: 'completed'`

`src/api/routes/bitcoin.routes.ts` — new route `POST /api/v1/bitcoin/split-payout` added before `export default router`. Required fields: `orderId`, `sellerBtcAddress`, `productSubtotalUsd`. Optional: `logisticsBtcAddress`, `logisticsCostUsd`. Validates order is `delivered` or `completed` before executing.

**L10 is NOT yet tested end-to-end.** Requires a delivered order with confirmed BTC in escrow, which needs the frontend quote picker (L12–L15) first. Code compiles cleanly, logic is correct. E2E test deferred to after L15.

**Commit:** `feat(bitcoin): L10 executeSplitPayoutBTC — seller + logistics split payout on delivery (S31)`

## Troubleshooting Reference

**API won't start:** Check `routes/index.ts` for empty or mis-exported route files.

**"TypeError: fetch failed" on scheduler:** Supabase is paused. Restore at supabase.com/dashboard, wait 30s.

**Blockstream 429:** Graceful since B12 (S30). Scheduler retries automatically next poll cycle.

**Logistics provider 403 on quotes/shipments (B5):** Dashboard requests data for old SatsFleet provider ID (`199e37cb`) when a new provider is logged in. Known bug, not blocking. Use Opportunities tab instead of dashboard stats for BitHaul.

**Seller logs in, can't see their products:** `SELECT did, email FROM identities WHERE email = 'their@email.com'` — should be exactly one row.

**Port conflict on 3000:** `rangkai-marketplace/package.json` dev script must be `next dev -p 3001`.

**Mnemonic rotation (if needed):**
1. `node -e "const bip39 = require('bip39'); console.log(bip39.generateMnemonic(256));"`
2. Replace `BITCOIN_MNEMONIC` in `.env`, set `BITCOIN_START_INDEX=0`
3. Restart API server — burn scan runs automatically

5. Store mnemonic securely offline. Never in version control.
