## Architectural Principles (Always-On)

1. Protocol is passive infrastructure — 0.5%+0.5% from payouts at escrow release, never added to buyer's total.
2. Federation is the goal from day one.
3. Cryptographic identity (secp256k1) — protocol never holds passwords/keys/KYC docs.
4. Nostr is plumbing, Rangkai owns UX and search.
5. Small business first — hide complexity. If something seems hard, check for the simpler framing first.
6. Bitcoin is the invisible rail — v1 pays out BTC/USD directly, invisible conversion is v1.5 (R11).
7. Terminology: seller, buyer, logistics — not vendor, provider, courier.
8. No centralized consolidation hubs — logistics stays inside the decentralized pool.

## Troubleshooting Reference

### API Server Won't Start
`Router.use() requires a middleware function but got a Object` → empty/misconfigured route file in `routes/index.ts`.

### "TypeError: fetch failed" on Startup
Supabase paused — restore at supabase.com/dashboard.

### SDK changes not taking effect
Full D25 sequence required. Verify: `findstr /n "methodName" rangkai-marketplace\node_modules\@rangkai\sdk\dist\modules\logistics.js`

### Direct quote request blinks back to browse state
Check API server terminal for the error. Most likely cause: `destination_country` field contains a full country name ("Singapore") instead of ISO code ("SG") — Zod schema rejects strings longer than 3 chars. Fix: type `SG`. Permanent fix: D19 (country autocomplete).

### `quote-requests/buyer/pending` returning 500
The nested Supabase join on `shipping_quotes` inside a `quote_requests` query fails due to ambiguous FK on `product_id`. Fixed S34 by splitting into two queries. If it resurfaces, check the two-query version is in place in `logistics.routes.ts`.

### Wrong provider showing in logistics-marketplace header
B5 — fixed S34. `ProviderContext` does client-side `.find(p => p.identity_did === did)`. Real fix (providers/me endpoint) in D34.

### Buyer sees wrong shipping price in cart
D35 — run the clean-up SQL above to restore the seller's standing accepted quote as the newest row. Permanent fix: D35 (`context` column on `shipping_quotes`).

### Opportunities page shows "Submit quote" on already-quoted requests
D34 part 2 — submitted state is session-local only. Refresh resets it. Permanent fix: pre-fetch provider's pending quotes on page load and mark those cards as quoted.
